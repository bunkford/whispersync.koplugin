# Kindle Whispersync for KOReader

A KOReader plugin that reads your **Send-to-Kindle library straight from
Amazon** and keeps **reading position, bookmarks, highlights and notes** in sync
with your Kindle account. It speaks the device protocol Kindle hardware speaks,
using everything this repo learned getting the dashboard to read *and write*
Amazon's sidecar.

Built for a jailbroken Kindle running KOReader (with or without Zen OS), but
nothing in it is Kindle-specific: it runs anywhere KOReader runs.

## Why another plugin

The existing `kindle.koplugin` reads books off the device and syncs by editing
the stock reader's KRDS sidecar files. That makes the stock reader the middleman:
your position only reaches Amazon when the stock reader next opens the book and
decides to sync, and it never learns about bookmarks made in KOReader at all.

This plugin cuts the middleman out:

| | kindle.koplugin | this plugin |
|---|---|---|
| Library source | files already on the device | Amazon (`syncMetaData`), downloaded on demand |
| Book format | converts KFX with a Python helper | Amazon serves Send-to-Kindle documents as plain MOBI; KOReader opens them natively |
| Position sync | KRDS sidecar files, via the stock reader | direct, verified write to Amazon's sidecar |
| Bookmarks / highlights / notes | — | both directions |
| Needs the stock reader | yes | only once per book (see *The guid*) |

## What it does

- **A shelf of your Kindle books**: covers, title, author and progress in a
  paged grid, like the dashboard's library view. Covers and metadata come
  from inside each book file (the same 32 KB header trick the dashboard uses),
  progress from Amazon's sidecar. Tap a book to download and open it; hold it
  for details, "Update progress", or to remove the downloaded copy. The menu
  (☰) refreshes from Amazon, sorts by recent / title / author, and filters.
- **On open**, checks Amazon. If a Kindle or the Kindle app has read further, it
  offers to jump there (or does so silently, or never — your choice). Bookmarks,
  highlights and notes made on the Kindle are imported.
- **While reading**, after 90 seconds of quiet, and again on close and suspend,
  your position is written to Amazon and **verified by reading it back**.
  Bookmarks, highlights and notes you make are pushed too; ones you delete are
  deleted upstream.
- **Sync status for this book** shows what is here, what Amazon holds and when,
  what was last sent from this device, and — via "Who wrote it?" — Amazon's own
  record of which device set the position. A **sync log** keeps the last 80
  events across restarts.
- **Conflicts** (both sides moved since the last sync) are never resolved
  silently: you are asked which position to keep.

## Install

### With ZenPM (recommended: updates arrive automatically)

1. In ZenPM, open **Sources → Add** and enter
   `https://bunkford.github.io/whispersync.koplugin/`
   (or `zenpm repo add whispersync https://bunkford.github.io/whispersync.koplugin/`
   over SSH). Refresh. If that host is unreachable from the device, the same
   repository is served at
   `https://raw.githubusercontent.com/bunkford/whispersync.koplugin/main/zenpm/`.
2. Install **Kindle Whispersync**. ZenPM's update checks then pick up every
   new release; **Installed → Update** applies it.

The source is a plain static ZenPM repository (`zenpm/manifest.json` plus the
package's `versions.json`) generated by the release workflow and published to
GitHub Pages; the package
itself is the `whispersync.koplugin.zip` asset of a GitHub release of this
repository. ZenPM compares the manifest version with the `version` field in
the installed `_meta.lua`, so a release is an update exactly when that field
went up.

### By hand

1. Download `whispersync.koplugin.zip` from the latest release and extract
   it, or copy the `whispersync.koplugin` folder from this repository, to
   `koreader/plugins/` on the device.
2. Restart KOReader. **Kindle Whispersync** appears under the Tools menu.
3. Connect your Amazon account (below).

Requires a KOReader from 2024 or later (it uses the unified annotations API).

## Connecting

Two ways. Both end with an `adp_token` and RSA device key stored in
`koreader/settings/whispersync.lua`. **They never expire**, so this is one-time.

### A. Reuse the dashboard's registration (recommended)

On the dashboard host (a checkout of this repository, or just the script):

```
python3 tools/export_device.py --config /path/to/kindle/secrets/config.json
```

Copy the resulting `whispersync_device.json` to the device as
`koreader/settings/whispersync_device.json`, then **Kindle Whispersync → Amazon
account → Import credentials from file**. Delete the file afterwards.

The Pi and the Kindle then sign as the same virtual device, which is harmless:
Amazon just attributes positions from both to the same device name.

### B. Register from the device, with your phone doing the typing

**Amazon account → Register this KOReader with Amazon → your store.** The
plugin starts a small web page on the Kindle's own Wi-Fi address (port 8123)
and shows one screen with the QR code, the address (e.g.
`http://192.168.1.42:8123/`), the three steps, and a live status line that
changes as the phone opens the page, pastes the code, and Amazon answers.

Open that on a phone or computer on the same Wi-Fi. The page has one button,
**Sign in to Amazon**, which opens Amazon's real sign-in page — password
manager, 2FA and passkeys all work, and nothing typed there reaches the
Kindle. Amazon lands you on a blank page; copy its address and paste it into
the box on the Kindle-served page. The Kindle exchanges the code, confirms on
its screen, and takes the page down. Nothing is typed on e-ink.

Pick the store your account actually lives on: the OAuth handle is per
country and registering a `.ca` account against `.com` is rejected.

If the page cannot be started (port busy, no listener support) the plugin
falls back to a QR code of the sign-in URL and a paste box on the Kindle.

The page is unauthenticated on your LAN for the minute or two it is up; the
worst a neighbour could do is register *their* Amazon account on your Kindle,
which you would notice immediately. Stop it any time from the menu.

#### Why not the Kindle's own login, or its browser?

Two obvious shortcuts were checked and don't pan out:

- **The Kindle is already signed in, so why register at all?** Stock
  firmware authenticates with a TLS client certificate
  (`/var/local/java/prefs/certs/client.p12`) against the `cde-g7g` hosts, a
  different scheme and host family from the ADP-signed `-ta-` hosts this
  plugin speaks. More importantly, Amazon chooses the download format from
  the device identity: a real Kindle's identity gets **KFX**, which KOReader
  cannot open. Presenting a legacy device type is exactly what makes
  Send-to-Kindle documents arrive as MOBI, so a separate registration is
  the feature, not a workaround. (Using the certificate only for position
  sync would still leave downloads needing their own registration.)
- **Sign in with the Kindle's browser instead of a phone?** You can point it
  at the connect page too, but the flow ends on a blank page whose address
  bar holds the code, and that address has to get from the browser into the
  plugin. On a phone that is one long-press; whether the Kindle browser can
  copy its own address bar varies by firmware and is untested here. The
  page works from either device; the phone is just the path of least
  resistance.

## Using it

**Kindle Whispersync → Kindle library** opens the shelf. The first visit
fetches the listing, then each book's header (title, author, ISBN, length,
cover) and current progress, with a dismissable progress message. Later
visits show the cached shelf at once and refresh quietly when the listing is
over five minutes old (Amazon asks for no more than one listing call per
300 s). Header data never changes and is fetched once; progress is refreshed
by ☰ → Refresh, or per book from its details.

Downloads go to `koreader/kindle-library/` by default — deliberately *outside*
`documents/` so the stock reader doesn't index them as duplicates. Change it
under **Library → Download folder**. Covers live in `covers/` beneath it.

Everything else is automatic. Reader menu: *Sync status for this book*,
*Sync this book now*, *Jump to Amazon's position*, *Send my position to
Amazon*, *Sync bookmarks, highlights and notes*, *Sync log*. Three dispatcher
actions (*Kindle library*, *Kindle: sync this book*, *Kindle: sync status*)
can be bound to gestures.

### Is it actually syncing?

Open **Sync status for this book**. "Last sent from here" is the position this
device wrote and had Amazon read back; "Amazon, most recent" is what Amazon
holds now. **Who wrote it?** asks Amazon's second oracle (`getAnnotations`),
which names the device credited with the position — if it says KOReader's
registration, the write landed. The sync log lists every decision with the
local and remote positions.

Two things that look like "not syncing" but aren't:

- KOReader writes **most recent read**. A Kindle's own "sync to furthest page
  read?" prompt appears only when the **furthest** position moves. Amazon
  raises furthest-read itself when you read past it, so reading *forwards* in
  KOReader shows up on the Kindle; reading *backwards* changes nothing there.
- The stock reader only asks Amazon when it opens the book (or on a manual
  "Sync"). Open the book on the Kindle with Wi-Fi on and give it a moment.

The dashboard's per-book "Get from Kindle" reads the same sidecar and shows
KOReader's position as the book's position.

## ZenOS

Everything here is on by default, so with ZenOS the Kindle library looks like
part of the device rather than a plugin:

- **A Kindle tab.** *Kindle Whispersync → ZenOS → Add a Kindle tab to the
  navbar* creates a native ZenOS folder tab pointing at the download folder.
  Your Kindle books appear in ZenOS's own cover view with its sorting, badges
  and progress. Restart KOReader once for the tab to show.
- **The whole library, locally.** *Library → Keep every personal document on
  this device* downloads all Send-to-Kindle documents during a refresh (files
  over 40 MB are skipped), which is what lets the native library, Recent and
  search see them. Turn it off to download only what you open.
- **Recent that knows your Kindle.** *Library → Feed Amazon read times and
  progress into history* puts each downloaded book into KOReader's reading
  history at the time it was last read on a Kindle and writes its progress and
  finished state into the book's sidecar. ZenOS's Home → Recent strip, progress
  badges and finished-book dimming read exactly those. A more recent read on
  this device is never overwritten.
- **A "Kindle" corner banner** on the cover of every Kindle book, drawn like
  ZenOS's own "New" banner: on the plugin's shelf and Home strip, on ZenOS
  Home (the Featured book, Recent and every other strip) and on ZenOS's
  library tiles. It sits in the top-left corner so ZenOS's progress badge and
  "New" banner keep the top-right; *Library → "Kindle" banner on covers* turns
  it off or moves it. *ZenOS → Banner on ZenOS covers…* shows which ZenOS
  screens it has reached.
- **Home strip.** ZenOS Settings → Library → Home → Widgets → *Kindle library*
  adds a strip of your most recently read Kindle books; tap one to open it.
- **Launcher / Controls → Add → Plugin menu → Kindle Whispersync** opens the
  cloud shelf (everything in the account, downloaded or not).

Zen Mode hides KOReader's Tools menu, where this plugin's settings live; reach
them through *Launcher → Add → KOReader submenu → Tools → Kindle Whispersync*,
or leave Zen Mode briefly.

The tab and the banner reach into ZenOS the same way ZenOS reaches into
KOReader, and every step is guarded: if a ZenOS update moves something, that
feature quietly switches off rather than breaking anything.

## How positions are mapped

A Kindle position for a Send-to-Kindle document is a **byte offset into the
decompressed MOBI HTML**. KOReader addresses text by xpointer. Percentages
would be the lazy bridge and are half a page off in a novel, so the plugin
does what the dashboard's browser reader does: it goes through the words.

On first open it decompresses the MOBI it downloaded (PalmDOC, trailing
entries stripped first — see the repo README for that trap), builds a
plain-text index mapping every visible byte to its raw offset, and caches it
beside the book's `.sdr`. Then:

- **xpointer → offset**: take the text of the node under the xpointer, find it
  in the index, add the character offset.
- **offset → xpointer**: take the words at that offset, search the rendered
  document for them (`findAllText`), take the hit.

Repeated phrases are disambiguated by the expected percentage; when hits are
too close to tell apart or the search cap is reached, the snippet is
lengthened until they aren't. Percentage is only the fallback (images, tables,
empty nodes), and the plugin tells you when it had to use it.

Highlights carry their own text, which is the most reliable anchor of all, so
a highlight made on either side lands on the same words on the other.

## The rules it follows

Every one of these was learned live against Amazon and is recorded in the
repo's README; each failure mode looks identical to "there is no write API":

- Only `kindle.most_recent_read` is written, never `kindle.lpr`: Amazon treats
  furthest-read as monotonic and raises it itself.
- The **real `guid`** goes on every write. `_LATEST_` returns 200 and is
  silently discarded.
- **No `key=` on the write URL**; `application/xml`; no prolog; no whitespace
  between elements; timestamps with colon-less offsets (`-0400`).
- The signature covers the exact body bytes sent.
- Position writes are **verified by read-back**. Annotation creates are paired
  by (kind, position ± 2 bytes) on read-back, because Amazon assigns the ids.
- Deletes trust the 200 (they are not read-after-write consistent); a delete
  that didn't take simply re-imports next time. **A note delete carries the
  note's text**, or the note stays.
- Bookmarks are sent with `mchl_color: dark_blue`, so they are
  indistinguishable from ones made on the hardware.
- Store purchases are DRM'd and are **never downloaded or decrypted**; the
  plugin refuses on `encryption != 0` before touching a text record.

## The guid

Amazon only accepts writes carrying a book's `guid`, and a book acquires one
the first time a Kindle (or the Kindle app) opens it. A document you send to
your Kindle and open *only* in KOReader has none yet: the plugin can read it
but its writes are dropped, and it tells you so. **Open it once in the stock
reader**; from then on it syncs.

## Limitations

- **PDFs** sent to Kindle are served as PDFs: no MOBI text, no byte positions.
  They download and open, but positions are not synced.
- **Store purchases** cannot be opened (DRM). Turn on *Show store purchases* to
  see them listed anyway.
- Sync needs Wi-Fi at the moment of the push. If the device is offline, the
  push is queued and happens when the network comes back or the book is next
  opened. A push on suspend is attempted while the radio is still up.
- Remote deletions (a bookmark removed on the Kindle) are *not* mirrored
  locally by default, because that is the one irreversible direction. Turn on
  *Remove local marks deleted on a Kindle* if you want them to be.
- Not yet run on real hardware by its author: the protocol code is the same as
  the dashboard's verified Python, the pure-Lua parts are tested (see below),
  but the KOReader glue in `main.lua` was written against the current API
  without a device to hand. Report anything odd with the KOReader log
  (`crash.log`, lines tagged `whispersync`).

## Releasing

```
# 1. add a "## X.Y.Z" section to CHANGELOG.md
# 2.
sh tools/release.sh X.Y.Z
```

That bumps `_meta.lua`, commits, tags `vX.Y.Z` and pushes. The `release`
GitHub Actions workflow then runs the tests, builds the archive
(`tools/build_plugin.sh`), publishes the GitHub release with the changelog
section as its notes, and regenerates `zenpm/` on the default branch
(`tools/zenpm_manifest.py`) so ZenPM users see the update.

To get into ZenPM's default catalogue as well, open a pull request or issue on
[xZenLabs/repo](https://github.com/xZenLabs/repo) adding a
`packages/koreader/whispersync.koplugin/.meta` that points at this
repository's releases; their generator scrapes the rest.


## Tests

```
whispersync.koplugin/tests/run.sh
```

Needs `luajit` (or `lua5.1`) and a Python with `cryptography` for the signing
fixtures. The tests cover: PalmDOC decoding against the Python decoder in this
repo, header parsing and trailing-entry stripping on a synthetic MOBI,
byte-exact ADP signatures against Python `cryptography` on both backends,
the exact wire format of every sidecar write, verify-by-read-back including a
detection of the `_LATEST_` silent discard, offset↔xpointer round trips on a
fake crengine document (including a phrase repeated 398 times), the
annotation reconciliation planner, catalog titles/sorting/status text, the
shelf's grid maths for three screen sizes, and — through stubbed KOReader
modules — the connect page's request handler, `posmap()` on the fixture, the
ZenOS launcher entry point, and book enrichment (header, cover, progress)
against a mock Amazon client.

## Credentials on disk

The device key is stored in plain text in `koreader/settings/whispersync.lua`,
which lives on the USB-visible partition. That is the same posture as the
dashboard's `secrets/config.json`. Anyone with the file can read your library
and set your reading positions; they cannot buy anything, and the registration
can be revoked from Amazon's *Manage Your Content and Devices* page.
